# R05 名单列表

> 来源：docs/需求.md 第 4 节「REQ-05 名单列表」、第 6.4 节（`/github-users`）、第 7 节 `githubUser.list`/`githubUser.tags`、第 8 节「性能」「可靠性」

## 背景与目标

管理员在 `/github-users` 看到所有已保存的用户，并能通过关键字、标签、排序和分页快速找到某个人。列表只读本地数据库，GitHub 不可用时也不受影响。

## 用户故事

- 作为管理员，我希望看到所有已保存的用户并能筛选排序，以便快速找到某个人。

## 验收标准

- [ ] R05-AC1：表格列为：头像、用户名、昵称、公司、所在地、粉丝数、公开仓库数、标签、最后同步时间、操作（本需求先提供「查看」，同步、删除、编辑在 R07～R09 加入）。
- [ ] R05-AC2：按关键字过滤，匹配用户名、昵称、公司、备注中的任意一个（包含即可，不区分大小写），只查本地数据库，不请求 GitHub。
- [ ] R05-AC3：按标签过滤，标签选项来自 `githubUser.tags`（所有用过的标签，去重排序）。
- [ ] R05-AC4：按添加时间、粉丝数、最后同步时间排序，升序或降序，默认按添加时间倒序。
- [ ] R05-AC5：分页由服务端完成，每页默认 20 条，可选 10、20、50；显示总数和页码。
- [ ] R05-AC6：关键字过滤、标签过滤、排序、分页能组合使用，结果正确。
- [ ] R05-AC7：筛选、排序、页码、每页条数体现在 URL 参数中，刷新页面后保持不变；参数不合法时回退到默认值。
- [ ] R05-AC8：1000 条数据时，列表接口响应时间小于 300ms。
- [ ] R05-AC9：名单为空时显示空状态，并提供「添加用户」入口；有筛选条件但没有结果时，提示没有匹配的记录并可以清除筛选。
- [ ] R05-AC10：页面处理加载中、空数据、出错三种状态；GitHub 不可用不影响列表。
- [ ] R05-AC11：从预览页（`/github-users/new`）加入用户后，名单列表里出现这条记录（由 R04-AC1 转来，在 R05 验收）。

## 不在范围内

- 列表行的同步、编辑、删除、批量删除（R07～R10）
- 导出

## 依赖
