# R03 查看 GitHub 用户资料

> 来源：docs/需求.md 第 4 节「REQ-03 查看 GitHub 用户资料」、第 6.4 节（`/github-users/new`）、第 7 节 `githubUser.lookup`、第 8 节「安全」

## 背景与目标

管理员从搜索结果（R02）中点选某人，或者直接粘贴 `/github-users/new?username=xxx` 链接，就能看到这个人的完整公开资料，确认是不是要找的人。这一步只预览，不写数据库。

## 用户故事

- 作为管理员，我希望在搜索结果中点击某个人就看到他的完整公开资料，以便确认后再决定是否加入名单。

## 验收标准

- [ ] R03-AC1：点击搜索结果中的某个用户，正常网络下 2 秒内显示完整资料卡片。
- [ ] R03-AC2：直接访问 `?username=` 指向一个不存在的用户名，提示「GitHub 上没有找到该用户」。
- [ ] R03-AC3：`?username=` 的格式不合法（不符合 1～39 位、字母数字和 `-`、不以 `-` 开头结尾、无连续 `--`）时，提示格式错误，不发请求；直接调用接口返回 `BAD_REQUEST`。
- [ ] R03-AC4：GitHub 限流时，提示「GitHub 请求过于频繁，请在 HH:mm 之后重试」，时间取自 GitHub 返回的重置时间。
- [ ] R03-AC5：GitHub 超时或不可用时，提示「GitHub 暂时无法访问，请稍后重试」。
- [ ] R03-AC6：已在名单中的用户，卡片上显示「已在名单中」和「查看」链接（到 `/github-users/{savedId}`），不显示「加入数据库」按钮。
- [ ] R03-AC7：资料卡片展示：头像、用户名、昵称、简介、公司、博客、所在地、公开邮箱、Twitter、公开仓库数、公开 Gist 数、粉丝数、关注数、GitHub 注册时间、GitHub 主页链接；为空的字段显示「—」。
- [ ] R03-AC8：卡片上有「返回搜索结果」，回到之前的关键字和页码；直接访问（没有搜索参数）时回到空的搜索页。
- [ ] R03-AC9：查询结果只用于预览，调用 `lookup` 不写数据库。
- [ ] R03-AC10：简介、博客等外部内容按纯文本显示，不使用 `dangerouslySetInnerHTML`；外链带 `rel="noopener noreferrer"`；博客只有 `http://` 或 `https://` 开头时才渲染为链接，否则显示为纯文本。
