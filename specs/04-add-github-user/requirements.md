# R04 加入数据库

> 来源：docs/需求.md 第 4 节「REQ-04 加入数据库」、第 5 节「数据模型」、第 7 节 `githubUser.create`

## 背景与目标

管理员在资料预览（R03）中确认无误后，一键把这个人存进名单。为保证数据可信，服务端重新从 GitHub 拉取最新资料再保存，并以 GitHub 数字 ID 判重。

## 用户故事

- 作为管理员，我希望确认资料后点一下就存进名单，以便之后集中管理。

## 验收标准

- [✅] R04-AC1：在资料预览点击「加入数据库」后，提示「已添加」，名单列表里出现这条记录；预览卡片随即变为「已在名单中」+「查看」。（名单列表展示部分转到 R05 验收，见 R05-AC11）
- [✅] R04-AC2：重复添加同一个用户，接口返回 `CONFLICT`，前端提示「该用户已在名单中」；两个请求同时添加同一个人时，也只有一条成功、另一条返回 `CONFLICT`。
- [✅] R04-AC3：用户名大小写不同（如 `Torvalds` 和 `torvalds`）视为同一个人（按 `githubId` 判重）。
- [✅] R04-AC4：数据库里保存的资料和 GitHub 当前的资料一致：前端只提交用户名，服务端不走缓存、重新请求 GitHub 后保存，`syncedAt` 为保存时间。
- [✅] R04-AC5：记录的 `createdById` 为当前登录用户的 `ctx.session.user.id`。
- [✅] R04-AC6：GitHub 上不存在、限流、不可用时，分别提示「GitHub 上没有找到该用户」、「GitHub 请求过于频繁，请在 HH:mm 之后重试」、「GitHub 暂时无法访问，请稍后重试」，不写数据库。
- [✅] R04-AC7：用户名格式不合法时返回 `BAD_REQUEST`；提交过程中按钮禁用，防止重复点击。

## 不在范围内

- 批量添加
- 添加时填写备注和标签（添加后在 R07 中修改）

## 依赖

- 依赖 R03 查看 GitHub 用户资料（预览页和「加入数据库」入口）
