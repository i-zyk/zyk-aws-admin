# R09 删除（物理删除）

> 来源：docs/需求.md 第 4 节「REQ-09 删除」、第 5 节（物理删除说明）、第 7 节 `githubUser.delete`、第 9 节决策 D2

## 背景与目标

管理员把不再关注的用户从名单里删掉。采用物理删除（D2），直接删除数据库记录，不做回收站；删错了可以重新搜索添加，但备注和标签会丢失，所以删除前必须确认。

## 用户故事

- 作为管理员，我希望把不再关注的用户从名单里删掉，以便名单保持整洁。

## 验收标准

- [✅] R09-AC1：列表行和详情页都有「删除」按钮，点击后弹出确认框，确认框里显示要删除的用户名，并提示「删除后无法恢复，备注和标签会一起删除」。
- [✅] R09-AC2：确认后记录从列表中消失，提示「已删除」，数据库中这条记录已不存在；从详情页删除后回到列表页。
- [✅] R09-AC3：点击取消，不发送删除请求。
- [✅] R09-AC4：删除一个已经不存在的记录，返回 `NOT_FOUND`，前端提示「记录不存在」后刷新列表。
- [✅] R09-AC5：删除后可以重新添加同一个 GitHub 用户（不会因为唯一约束冲突）。
- [✅] R09-AC6：删除进行中确认按钮禁用，防止重复提交。

## 不在范围内

- 回收站、恢复（D2 明确不做）
- 批量删除（R10）
