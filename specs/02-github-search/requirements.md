# R02 模糊搜索 GitHub 用户

> 来源：docs/需求.md 第 4 节「REQ-02 模糊搜索 GitHub 用户」、第 6.3 节「GitHub 调用规则」、第 6.4 节（`/github-users/new`）、第 7 节 `githubUser.search`、第 9 节决策 D3

## 背景与目标

管理员往往只记得对方用户名或昵称的一部分。「添加用户」页面先提供关键字搜索，列出可能的人，再从中挑选进入资料预览（R03）。GitHub 搜索额度很少（无 token 每分钟 10 次、有 token 每分钟 30 次，所有用户共用），所以只在点击按钮或按回车时搜索，并配合缓存。

## 用户故事

- 作为管理员，我希望输入关键字就能列出匹配的 GitHub 个人用户，以便从中挑出我要找的人。

## 验收标准

- [ ] R02-AC1：在 `/github-users/new` 输入 `linus` 点「搜索」（或按回车），正常网络下 2 秒内列出匹配的用户，每页 10 条，并显示总数；每行显示头像、用户名、GitHub 主页链接。
- [ ] R02-AC2：输入 `torvalds` 搜索，`torvalds` 排在本页第一位，并标出「精确匹配」（用户名与关键字不区分大小写完全相同）。
- [ ] R02-AC3：已经在名单中的用户，在结果中标出「已在名单中」（服务端按 `githubId` 批量查数据库）。
- [ ] R02-AC4：没有结果时显示「没有找到匹配的 GitHub 用户」。
- [ ] R02-AC5：关键字去掉首尾空格后为空或超过 100 个字符时，前端直接提示，不发请求；直接调用接口时返回 `BAD_REQUEST`。
- [ ] R02-AC6：搜索额度用完时，提示「GitHub 搜索过于频繁，请在 HH:mm:ss 之后重试」，时间取自 GitHub 返回的重置时间。
- [ ] R02-AC7：「上一页」「下一页」翻页正确；关键字和页码体现在 URL（`?q=&page=`）中，从资料预览返回后关键字和页码保持不变。
- [ ] R02-AC8：总数超过 1000 时，提示「结果太多，请输入更具体的关键字」，最多只能翻到第 100 页；接口的 `page` 超过 100 返回 `BAD_REQUEST`。
- [ ] R02-AC9：只在点击「搜索」或按回车时发起搜索，输入过程中不请求；同一关键字和页码 60 秒内重复搜索不会再次请求 GitHub；窗口重新聚焦不会自动重新搜索。
- [ ] R02-AC10：只搜索个人用户（`type:user`），不包含组织；浏览器不直接请求 GitHub；搜索结果不写数据库。
- [ ] R02-AC11：点击某一行进入该用户的资料预览（`/github-users/new?username=<login>`，同时带上当前的 `q` 和 `page`）。
- [ ] R02-AC12：GitHub 超时或不可用时，提示「GitHub 暂时无法访问，请稍后重试」；搜索中显示加载状态。

## 不在范围内

- 边输入边搜索（PRD 明确不做）
- 按地区、粉丝数等高级条件搜索
- 资料预览本身（R03）
